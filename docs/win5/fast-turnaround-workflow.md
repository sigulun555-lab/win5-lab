# WIN5 次回運用：即時予想・段取り短縮ルール

更新: 2026-10-25 JST
目的: オッズ確認後、予想提示までの待ち時間を短縮する。既存の予想・確率・監査ルールは変更しない。

## 最重要ルール
**最初に買い目候補を短時間で提示し、その後に詳細検証を続ける。** 全データ収集や長期モデル検証が終わるまで、ユーザーに予想を出さずに待たせない。ただし、未確認の情報を確認済みと偽らず、暫定/確定の状態を明示する。

## 実行順（次回の標準手順）

### 0. 締切を最初に確認
- 日本時間の現在時刻、WIN5対象5レース、最初の対象レース発走時刻、発売締切（通常は最初の対象レース発走5分前）を確認。
- 締切済みなら「購入可能な最終予想」とは言わず、事後検証・次回用として扱う。
- 締切まで残り時間を最初の回答に明記する。

### 1. リポジトリを再利用（探索を繰り返さない）
- まず main の data/win5_joint/YYYY-MM-DD/ と docs/win5/ を確認。
- 既存の対象レース、出馬表、全馬確率、朝の候補、前回の市場スナップショットを再利用し、同じデータを取り直さない。
- odds-data は自動オッズ保存用として扱う。手作業の共通文書・買い目・評価メモは原則 main に置く。odds-data の内容を使う場合はリンク/時刻/出典を明記する。
- ユーザーやClaudeが取得中と明示した馬履歴データは重複取得しない。取得済み範囲・SHA256の報告を待つ。

### 2. 最小限の当日確認を一括で行う
- JRA公式WIN5対象一覧と各5レースの出馬表を確認。
- 馬番・馬名・取消/除外・斤量・騎手・馬場を確認。
- 市場比較を使う場合、対象5レースのオッズを可能な限り同じ短い時間帯にまとめて取得し、取得時刻と出典をレースごとに記録する。時刻が揃わない場合は「非同期スナップショット」と明記。
- 締切直前は、長期履歴の再構築より、公式出走情報・取消・最新オッズ・既存候補の確認を優先する。

### 3. まず短い回答で買い目候補を提示
- データ確認後、最初の実用的な回答で「5レースの馬番」「点数」「100円あたり合計」「締切までの残り時間」を出す。
- 既存のGPT探索順位と市場順位が食い違う場合、どちらを採ったかを1行で説明する。
- 買い目を一意に決める根拠が不足する場合は「暫定候補」と明記する。予想の確定を装わない。
- 買い目を複数案で提示する場合は、標準案を1つ先に出し、予算別の代替は短く添える。
- 購入操作を行ったと主張しない。購入はユーザー本人が判断する。

### 4. 深掘り監査は回答後に継続
- 全馬確率の合計、頭数・馬番の突合、モデル対市場の順位差、履歴欠損、データ時刻の監査を後続作業として進める。
- 追加監査の結果で予想を変える場合、変更点・理由・変更時刻を明記し、元の候補を上書きせず両方保存。
- 締切後は「締切前に見えていた情報」と「結果を見てから得た情報」を分ける。結果を使って当日の予想を事後修正しない。

## 予想を固定する時の保存先・記録項目
- 保存先: main の docs/win5/YYYY-MM-DD-final-picks-asof-HHMM-jst.md（参照用の人間可読な買い目）と必要なCSV/JSON。
- 必須項目: 予想基準時刻、締切、対象レース、各レースの選択馬番・馬名、組合せ数、想定金額、オッズ取得時刻/出典、判断根拠、未確認事項、モデル状態（検証済み/探索的）、コミットSHA。
- オッズ自動保存処理と競合しないよう、手作業成果物を odds-data の自動保存ファイルに直接書き込まない。

## 守るべき品質ルール
- 早く出すことは、確認していない情報を事実として断言することではない。
- 市場オッズでGPT独自確率を上書きしない。市場確率は別列として保持。
- 未検証モデルを「正式モデル」「精度改善済み」と呼ばない。
- 5レースすべての馬番を出し、点数と合計金額を計算検算する。
- 最新オッズは変動するため、取得時刻を表示し「締切直前まで同じ」と誤認させない。
- 結果がわかる前に固定した予想と、事後の採点記録を分離する。
