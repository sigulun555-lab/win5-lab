# Claudeレビュー結果：WIN5履歴のみモデルの評価コードと検証計画（2026-10-25）

対象：`scripts/evaluate_win5_history_only.py`（レビュー依頼書の確認対象 `1e45161`）と周辺。
予測CSV・モデル確率は一切変更していない。結果を見て予測を直していない。

## 1. 重大な問題

**評価スクリプトが、実際の確率CSVを読めなかった（修正済み）。**
`data/win5_joint/2026-10-25/gpt-exploratory-history-only-probabilities.csv` は `leg` を `1.00000`、
`horse_number` を `1.00000` の形（浮動小数）で保存している。旧スクリプトは文字列のまま `{"1".."5"}` と比べるため、
このCSVでは必ず `ValueError: Expected prediction rows for all five legs` で止まっていた
（結果CSVを仮に用意して実行し、再現を確認）。結果確定後に初めて動かして失敗する形だった。
→ 数字を整数として読むよう修正（`1`、`01`、`1.00000` を同一視）。実CSVの形式を使うテストを追加。

その他の欠陥（いずれも修正済み）：
- 結果テンプレートが空欄のままでも、`winner  matched 0 times` という分かりにくい失敗になっていた
  → 「公式結果が未入力」と明示して止める。
- 同じレグの結果行が2行あると、後の行が黙って採用されていた → 重複はエラー。
- 取消・除外の扱いがなかった → 結果CSVの任意列 `scratched_nos` を除外して評価時のみ再正規化（予測ファイルは不変）。
  勝ち馬が除外扱い、または予測にない馬番はエラー。
- Top-1／Top-3の同点が入力順で決まっていた → 馬番の小さい順で決め、警告を出す。
- 勝ち馬の確率が0のとき、Log lossが 34.5（1レース）になることが黙って混ざっていた → 下限を引数化し、警告を出す。
- 列名が固定（`gpt_exploratory_win_probability_pct`）で、Claudeや市場の列を評価できなかった
  → `--probability-column`、`win5_order`／`horse_no` の別名に対応。

## 2. 指標定義（既存スクリプトとの整合）

| 指標 | evaluate_win5_predictions.py | evaluate_win_probabilities.py | 旧 history_only |
|---|---|---|---|
| 勝ち馬Log loss | 平均 -ln(p)、下限1e-15 | 同左 | 同左 |
| Brier | 全頭プール（合計÷総頭数） | レース平均（レースごとに÷頭数→平均） | 全頭プール |

**Brier/馬は、頭数が多いほど機械的に小さくなる**（全頭同確率でも 1/n に比例）。2026-10-25は 9／15／17／16／18頭、
2026-10-24は 15／16／12／16／13 頭のように、日によって頭数が違うので、日をまたいだ比較に使えない。
全頭プールは、大きなフィールド（例：菊花賞18頭）に重みがかかる。

→ 新スクリプトは3つを併記する：全頭プール（キー `multiclass_brier_per_horse`、旧と互換）、
レース平均（`brier_per_horse_race_mean`）、レース合計の平均（`multiclass_brier_race_sum_mean`、通常のmulticlass Brier）。
さらに、全頭同確率（1/頭数）の基準値を併記する。モデルの価値は、基準との差で見る。

検算：2026-10-24の結果で、GPT 11:06 の列を新スクリプトで再計算すると、
ChatGPT側の数値（`fast-model-validation-status-2026-10-25.md`）と一致した。
Top-1 2/5、Log loss 2.03361、Brier/馬(プール) 0.057290。

| `data/win5_races/`（9/26〜10/24、45レース） | **◎の勝率1つ＋◎○▲のみ** | **なし**（`timestamp`は日付のみ、予想時刻なし） | △（◎的中率とキャリブレーションの参考のみ） |

`data/win5_races/` と公式結果（10/3〜10/18、35レース）を突き合わせた参考値：
◎の的中 12/35（34%）、◎○▲に1着馬が入ったのは 20/35（57%）、記録された◎の勝率の平均 36.8%。
ただし、**予想時刻の記録がなく、発走前に保存されたことを証明できない**。後から入力された可能性を排除できないため、
モデル精度の証拠としては扱わない（キャリブレーションの目安にとどめる）。

**結論：全頭の確率を発走前に保存した、結果つきの過去開催は、今のところ10/24の1開催だけ。**
複数開催のバックテストは、今日以降に蓄積するデータで成り立つ。過去開催の発走前の全頭確率を、後から再構成することはできない
（当時のオッズも、保存されていない）。

## 5. 2026-10-25の結果評価の準備

- `collector/fetch_win5_results.py`：公式一覧の並びで5レースを決め、開催日結果ページから1着馬を取り出す。
  未確定・同着・欠けがあるときは何も書かず終了コード2（推測で埋めない）。取消・除外は `scratched_nos` に出す。

  2026-10-25は、まだレースが終わっていないため、書き出されないことを確認（終了コード2）。
- 予測CSVは変更しない。結果は別ファイル（`win5_official_results.csv`）に保存し、評価は読み取りのみ。
- 実行は、全5レース確定後（16:00以降）。コマンドは `docs/win5/history-only-evaluation-runbook.md` に記載。

## 6. 検証精度を上げるために（優先順位順）

**今すぐ必要なもの**
1. **予測の保存を型にする**：予測作成時に、日付・モデル版・予測時刻・オッズ時刻・確率CSV・SHA256を1つのメタファイルに保存する
   （`freeze_win5_v1.py` がすでにあるので、朝／直前の両方で使う）。これがないと、後から「発走前」を証明できない。
2. **結果取得と評価を、1つのコマンドにつなぐ**：16:00以降に `fetch_win5_results.py` → `evaluate_win5_history_only.py`
   （GPT・Claude・市場の3列）を実行。今回追加した部品で、すぐ動く。
3. **市場確率を同時点で並べる**：締切5分前（第10項）のオッズから作った市場確率を基準列にし、
   モデル・市場を同じ指標・同じ時点で比べる。全頭同確率の基準も併記する。

**データが揃ってからでよいもの**
4. 開催を単位にした時系列分割（前半で調整、後半を最終テスト）。目安は、20開催（100レース）以上。
5. キャリブレーション（確率帯ごとの実際の勝率）、市場との差の有意性（レース単位のブートストラップ）。
6. 本物のオッズでの二段目（市場を土台にして、効果が確認できた要素だけを足す）。`odds-data` が数週間分たまってから。
7. 全頭のオッズの履歴がない過去開催は、確率評価に使わない（結果だけのデータでは、確率の評価ができない）。

## 7. 注意

- 1開催5レースでは、モデルの優劣を判断できない。10/24の数字（GPT Top-1 2/5、Claude Top-1 1/5 など）は、偶然の範囲。
- GPT 11:06、Claude 14:27、市場 14:40 は、同じ時点ではない。
