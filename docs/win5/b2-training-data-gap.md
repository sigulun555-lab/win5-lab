# B2学習データの所在監査

更新: 2026-10-25

## 目的

B2の係数推定に進む前に、検証プロトコルで必要なデータがリポジトリに存在するかを確認する。監査スクリプトは `scripts/audit_b2_training_sources.py`。

## 現在の判定

現行のリポジトリツリーでは、既存の検証コードが参照する `research/factor-validation/races.json` を確認できない。これがない状態では、B2と人気順位のみのモデルを同じ全レースで再現可能に比較できない。

- `data/horse_history/2026-10-25.json` は出走馬の過去履歴スナップショット。これだけでは全レースの勝者・人気を持つ学習用レース表にはならない。
- `data/win5_races/*.json` はWIN5対象レースの候補馬と予想情報であり、過去の全出走馬の実際の着順・人気を持つラベル付きデータの代用にはしない。
- 既存の `result_*.json` は以前の検証結果の記録であり、元データがリポジトリにない場合に再現可能性を補うものではない。

## 次の作業

1. 元のJRA公式結果ページから構築したレースデータの保存場所を確認する（HTMLが未追跡ファイルや別環境にないかも確認）。
2. 復元できる場合は、取得元・取得日時・対象期間・SHA256・スキーマを記録し、元データを変更せず保全する。
3. 日付、競馬場、レース識別子、馬ID、着順、人気の存在と一意性を監査する。
4. 各対象レースについて、その日より前の履歴だけが特徴量に入ることをテストする。
5. その後に限り、事前登録済み期間分割でB・B2・人気順位のみを比較する。

データが見つからない場合、候補馬JSONから結果を推測して埋めたり、履歴スナップショットを全期間データとみなしたりしない。B2は検証完了まで未採用とする。
